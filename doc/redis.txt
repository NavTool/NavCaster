Redis内部存储的Key和结构设计说明

CASTER:MASTER  
类型：STRING
作用: 当前的主节点的UID， 用于各个子节点选主

CASTER:NODE    
类型：HASH （Field：UID  Value：Json格式状态信息  TTL：周期重置）
作用：记录各个节点上报的状态信息


ACT:REC:XXXX
类型: HASH （Field：UID  Value：上线时刻UTC秒  TTL：周期重置）
作用：记录使用此账号登录的连接的UID，用于判断当前账号连接数是否已经超过限制，超过限制后踢出账号

    
ACT:UND:XXXX
类型：HASH （Field：UID  Value：上线时刻UTC秒  TTL：周期重置）
作用：记录使用此账号匿名登录的连接的UID，用于与注册账号做区分 


ACT:ACCOUNT     // 账号注册表
类型：HASH （Field：UID与用户名一致  Value：Json账号信息  TTL：不过期）
作用：记录已经注册的账号

ACT:ACTIVE      // 激活账号表
类型：HASH （Field：UID与用户名一致  Value：Json账号信息  TTL：不过期）
作用：记录当前可用的账号（未过期，未失效账号），用户验证的时候会查找这个表

ACT:UNNAMED      // 匿名账号记录表
类型：HASH （Field：BaseAuth  Value：最后登录时刻UTC秒  TTL：不过期）
作用：记录登录过的匿名账号


MPT:LIST
类型: HASH （Field：挂载点名  Value：上传的挂载点信息  TTL：周期重置）
作用：记录所有在线挂载点的数据流信息，用于构建源列表（这个挂载点信息的来源）

MPT:STAT
类型：HASH （Field：UID  Value：Json连接状态信息  TTL：周期重置）
作用：记录所有在线基站连接的数据流信息

MPT:REC:XXXX
类型: HASH （Field：UID  Value：上线时刻UTC秒  TTL：周期重置）
作用：记录使用此挂载点登录的连接的UID，用于多节点解决挂载点重复登录，并实现踢出先登录/后登录账号功能

MPT:SUB:XXXX
类型: HASH （Field：UID  Value：上线时刻UTC秒  TTL：周期重置）
作用：记录所有订阅此基站的的连接的UID

MPT:GEO
类型：GEO   （Member：挂载点名  Score：经纬度）
作用：用于最近点功能（只有解析到坐标的基站才能被订阅到，即使添加进去之后，也会判断是否在线，所以不做删除操作，内部可能存放了无效的挂载点）

USR:LIST
类型: HASH （Field：用户名  Value：用户上线时刻UTC秒  TTL：周期重置）
作用：记录所有在线挂载点的数据流信息，用于构建源列表

USR:STAT
类型：HASH （Field：UID  Value：Json连接状态信息  TTL：周期重置）
作用：记录所有在线基站连接的数据流信息

USR:REC:XXXX
类型: HASH （Field：UID  Value：上线时刻UTC秒  TTL：周期重置）
作用：记录使用此用户名的连接的UID

USR:SUB:XXXX
类型: HASH （Field：UID  Value：上线时刻UTC秒  TTL：周期重置）
作用：记录所有订阅此用户的连接的UID

USR:GEO
类型：GEO   （Member：UID  Score：经纬度）
作用：数据记录



GROUP:LIST      // 策略组列表
类型：HASH （Field：UID  Value：Json分组配置信息  TTL：不过期）
作用：记录所有的策略组

GROUP:MPT:XXXX
类型：HASH  （Filed：挂载点名  Value： 挂载点配置信息）
作用：记录指定策略组所有挂载点的行为
        控制这个策略组所有允许使用的挂载点（包括实体挂载点、虚拟挂载点）
        控制每个挂载点的显示策略（上线显示、始终隐藏、始终显示）
        配置这个挂载点的类型（普通挂载点，最近挂载点）




应用场景1：完全匿名模式
基站和用户都使用匿名登录，完全不做权限控制，用户可以看到所有的基站，显示最近挂载点模式

    基站开启匿名登录
    用户开启匿名登录
    默认权限组配置：启动最近点模式，可见非组内基站，可获取非组内基站数据，非组内基站参与最近点检索


应用场景2：用户管理模式
基站使用匿名登录模式，用户使用注册模式，用户可以看到所有的基站，可以显示最近挂载点模式

    基站开启匿名登录
    用户关闭匿名登录，所有用户注册到默认权限组
    默认权限组配置：启动最近点模式，可见非组内基站，可获取非组内基站数据，非组内基站参与最近点检索


应用场景3：严格用户管理模式
基站和用户均使用账号密码登录，用户可以看到所有的基站，可以显示最近挂载点模式

    基站关闭匿名登录
    用户关闭匿名登录，所有用户注册到默认权限组
    默认权限组配置：启动最近点模式，可见非组内基站，可获取非组内基站数据，非组内基站参与最近点检索

应用场景4：权限管理模式
基站和用户均使用账号密码登录，用户可以看到部分基站，可以使用最近挂载点模式

    基站关闭匿名登录
    用户关闭匿名登录，所有用户注册到默认权限组
    默认权限组配置：启动最近点模式，关闭可见非组内基站，关闭可获取非组内基站数据，关闭非组内基站参与最近点检索


应用场景5：仅最近挂载点模式
基站和用户均使用账号密码登录，用户仅可使用最近挂载点，实体基站不可用

    基站关闭匿名登录
    用户关闭匿名登录，所有用户注册到默认权限组
    默认权限组配置：启动最近点模式，关闭可见非组内基站，关闭可获取非组内基站数据，开启非组内基站参与最近点检索

应用场景6：基站别名模式
用户无法看到实体基站，仅能看到别名基站，连接别名基站自动转接到实体基站数据流

    默认权限组添加指定别名基站
    默认权限组配置：关闭最近点模式，关闭可见非组内基站，关闭可获取非组内基站数据，开启非组内基站参与最近点检索


应用场景7：混合模式
用户可以看到部分实体基站，部分实体基站隐藏，显示别名基站

    默认权限组添加需要隐藏基站，需隐藏基站配置不可见，不可获取数据
    默认权限组配置：关闭最近点模式，可见非组内基站，可获取非组内基站数据

应用场景8：分用户组执行不同的策略模式
    匿名用户：仅可见部分挂载点和数据，无最近点模式
    用户组A可见所有实体基站，以及最近挂载点
    用户组B可见指定区域内实体基站，以及最近挂载点（最近挂载点可用全部所有基站）
    用户组C可见最近挂载点，可实际接入所有实体基站
    用户组D可见

    默认策略组：关闭非组内可见，关闭获取非组内数据，关闭最近点模式
    策略组A： 开启非组内可见，开启最近点，开启非组内基站参与最近点检索
    策略组B:  添加需要可见的基站，开启最近点，开启非组内基站参与最近点检索
    策略组C： 关闭非组内可见，开启获取数据，开启非组内检索，显示最近点


综上：
    1、每个用户归属一个策略组
    2、每个策略组有若干基站，以及配置支持最近参考站
    3、可以控制策略组内每个基站的可见状态、能够获取数据、是否参与最近基站数据播发
    4、策略组内的基站可以是实体基站，别名基站

    5、所有匿名用户共用一个策略组（default）
        策略组除了能控制已经添加到策略组的基站的状态，也能够控制未添加到策略组的基站（实体基站的状态）
            非组内基站可见状态
            非组内基站能否获取数据
            非组内基站是否参与最近基站数据播发

        别名基站和实体基站均可以属于非组内基站（别名基站也算是一个实体的基站）
